Factory Inventory Management System

A demo full-stack application: a Vue 3 single-page app talking to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Three layers, two processes. The browser runs the SPA; the API process owns all data and filtering.

Data flow

How a filter change on screen becomes an updated chart.

  1. Select. The user changes Time Period, Warehouse, Category or Order Status in FilterBar. State lives in the shared useFilters composable.
  2. Request. getCurrentFilters() builds a filter object; api.js drops any value equal to all and sends the rest as query parameters.
  3. Filter. The route calls apply_filters (exact warehouse, case-insensitive category and status) and filter_by_month (a month such as 2025-09 or a quarter such as Q3-2025, matched against order_date).
  4. Validate. Results pass through the Pydantic response_model, then return as JSON.
  5. Render. The view stores the response in a ref; computed properties derive totals and chart series, and Vue re-renders.

Observations

Client and server are out of sync. client/src/api.js calls /api/tasks (get, create, delete, toggle) and /api/purchase-orders (create, get by backlog item), and main.py defines a CreatePurchaseOrderRequest model. But main.py has no routes for either, and no POST, PUT or DELETE routes at all. Those client calls will return 404 until the endpoints are added.
  • The API base URL is hard-coded in api.js, so the frontend only works against a local backend on port 8001.
  • Data is in memory and reloaded from JSON on restart; nothing written at runtime persists.
  • Inventory has no time dimension, so the month filter does not apply to it.
